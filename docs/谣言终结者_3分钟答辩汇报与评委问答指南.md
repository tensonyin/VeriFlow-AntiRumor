本指南专为**第九届全国青少年人工智能创新挑战赛 - AI智能体设计开发专项赛**决赛答辩编写。采用**“现场演示直接切入 $\rightarrow$ 后台与硬件异步讲解 $\rightarrow$ 切回演示展示结果与长辈模式”**的互动式逻辑，演讲词经过口语化润色，更适合现场自然、有感染力地宣讲。

## 🔍 第三部分：评委硬核技术问答库 (口语化提炼)

评委提问时，回答要**言简意赅、直击痛点**，避免大段念稿，要用最自信的口吻讲清技术原理：

### 📥 一、 工作流与智能体博弈 (Workflows & Multi-Agent)

#### Q1: 大模型核查时，经常胡乱生成一些打不开的网址（幻觉），你们怎么解决？
*   **🎤 回答模板**：
    > 我们的系统有自动纠错能力。我们在后台设计了一个 **Compliance Agent（合规智能体）**。它在拿到大模型的初版报告后，会自动在后台的沙箱里跑一段 Python 脚本，并发去测试报告里引用的每一个网页链接。
    > 一旦发现 404 或者打不开的死链，直接过滤掉，并命令大模型“自我反思、重新改写报告”，彻底把死链和瞎编的网址抹掉，保证给长辈看的证据 100% 真实。

#### Q2: 你们这个“红蓝智能体博弈对抗”是怎么玩的？为什么不直接让大模型联网查？
*   **🎤 回答模板**：
    > 直接让大模型联网查，模型很容易“随大流”或者偏信自媒体。我们模拟了“真相法庭”：
    > *   **正方（取证探员）**：负责多源检索。如果流言涉及海外背景，它会自动把中文翻译成英文，加上 `hoax`（骗局）或 `debunk`（辟谣）这类关键词去全球检索，把正面事实和权威信源捞回来；
    > *   **反方（审计探员）**：故意不给它联网。它纯粹靠科学常识和逻辑去挑刺，死磕文本里有没有“剂量缺失”、“偷换概念”或“情绪恐吓”的洗脑套路；
    > 最后由中立的“大法官”把两边报告合在一起做交叉比对，做出证实、伪造或存疑的判定。这样得出的结论才经得起推敲。

#### Q3: 什么是“材料充分性校验”？如果有人故意输入乱码或者无意义的冷门词，系统会死机或强行辟谣吗？
*   **🎤 回答模板**：
    > 绝对不会。我们设计了一个条件拦截路由。如果用户输入的文字太简短、是乱码、或者根本不包含任何可查证的事实（比如只输入“火星人苹果”），红蓝双方都抓不到任何有效数据。
    > 这时候系统会智能拦截，不走后面的判决流程，而是直接路由到“异常输出”节点，温馨提示长辈补充信息。这样既保护了算力，也防止了大模型“无中生有”地瞎编乱造。

### 💻 二、 前后端核心技术突破 (Frontend & Backend)

#### Q4: 前端在保存“辟谣小票长图”时，如果图片是别家网站的，Canvas 截图会因为跨域污染报错，怎么解决？
*   **🎤 回答模板**：
    > 这是前端开发最头疼的 `html2canvas` 跨域图片报错。
    > 我们的解决方案是在我们的 Node/Express 服务端写了一个**同源图片代理接口**。前端在把 Markdown 渲染成辟谣小票时，会用正则把所有外网图片的地址拦截，重定向到我们的代理服务。浏览器会认为这些图片是同源的，从而顺利截图，秒级导出朋友圈长图。

#### Q5: 长辈模式字体放大了1.5倍，Mermaid 脑图里的文字不会重叠或者挤出屏幕吗？
*   **🎤 回答模板**：
    > 我们开发了一个高精度的响应式组件：
    > 首先，系统会在渲染时向 SVG 脑图内部动态注入局部 CSS 样式，强制增大字距和边距；
    > 其次，我们集成了 `d3-zoom` 交互机制。长辈在屏幕上可以像放大手机照片一样，用手指捏合、拖拽这个图表。哪怕字再大，划一划、捏一捏就能看得很清楚，彻底解决了大字号下文字堆叠的问题。

#### Q6: LaTeX 渲染大字报海报时，中文字体经常挤在一起，怎么调好的？
*   **🎤 回答模板**：
    > 针对前端 MathJax 渲染 LaTeX 时中文重叠的缺陷，我们做了个“转义小套路”：
    > 在大模型生成 LaTeX 源码时，我们在提示词里加了硬约束，要求它在每个汉字和中文标点之间，必须强行塞进一个“`\ `”转义空格或“`．`”点号。这相当于在模型输出时就强制为每个汉字开了排版空间，渲染出来的大字报就非常工整美观。

### 📟 三、 行空板硬件与适老优化 (Hardware & Elderly-Friendly)

#### Q7: 行空板体积太小，扬声器声音不够大，老人怎么听？
*   **🎤 回答模板**：
    > 我们设计了一个**“远程 Web 扬声器中转机制”**。
    > 老人按下行空板物理键录音并上传，后端 Dify 跑完工作流、用 edge-tts 合成好安心语音后，后端并不会在行空板本地播放，而是把语音播放指令和音频流直接通过 SSE 广播推给家里连着网的 Web 客户端（比如电脑或者平板）。
    > 这样，我们直接**借用电脑或大电视的优质音箱把声音放出来**，完美化解了微型硬件的音频限制。

#### Q8: 行空板上的 Python 程序如果显示带有 Emoji 表情的内容，Tkinter 引擎会闪退，这怎么处理？
*   **🎤 回答模板**：
    > 行空板的 GUI 绘制库底层不支持表情符号（Unicode 大于 0xffff 的非 BMP 字符），一画就抛异常闪退。
    > 我们写了一个**表情清洗装饰器**。在物理屏要绘制大模型安心文本之前，正则拦截并把所有 Emoji 洗涤干净，确保行空板硬件程序 100% 稳定运行。

#### Q9: 你们的长辈模式中，为什么要用一条绿色进度条来遮住后台的详细思考日志？
*   **🎤 回答模板**：
    > 调查核查需要 20 秒，普通模式展示实时日志，年轻人会觉得有科技感。
    > 但老年人对大堆难懂的代码和英文日志会感到信息过载，甚至会产生“系统是不是死机了”的二次焦虑。
    > 所以我们在长辈模式把细节全部藏起来，换成一条温暖、高对比度的绿色图形进度条，配合拟物的打字刷刷声。这在心理学上能给老人很强的确定感和陪伴感，消除空白等待焦虑。
